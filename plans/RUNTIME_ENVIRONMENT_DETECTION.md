# Runtime Environment Detection Implementation Plan

## Overview

Implement runtime verification of environment configuration by reading the actual Firebase project ID and comparing it against build-time constants. This prevents UI from displaying incorrect environment information when build configuration has bugs.

**Problem:** Build-time env variables can be wrong, causing UI to show "STAGING" while connected to production Firebase.

**Solution:** Read actual Firebase project ID at runtime and verify it matches claimed org/env.

**Principles:** SRP, KISS, modularity, pure functions for business logic, minimal testing.

## Implementation Steps

### Step 1: Create Data Model and Pure Function

**File:** `lib/config/environment_detector.dart`

**Requirements:**
- Create `EnvironmentDetectionResult` data class (use Freezed)
  - Fields: `actualOrg`, `actualEnv`, `claimedOrg`, `claimedEnv`, `isMatch`, `warningMessage`
  - Computed getter: `hasMismatch` → returns `!isMatch`
- Create project ID mapping constant `_projectIdToEnvironment`
  - Map structure: `'project-id': ('org', 'env')`
  - Include: `rescuenet-7733b` → production, `rescuenet-testing` → staging
  - Make it easy to extend for future orgs
- Create pure function `detectEnvironmentFromFirebase()`
  - Parameters: `actualProjectId`, `claimedOrg`, `claimedEnv`
  - Returns: `EnvironmentDetectionResult`
  - Logic:
    1. Look up actual org/env from project ID mapping
    2. Compare with claimed values
    3. If match: return success result
    4. If mismatch: return result with warning message
    5. If unknown project ID: return result with "unknown" warning

**Implementation Notes:**
- Use Freezed for immutability: `@freezed class EnvironmentDetectionResult`
- Pure function = no side effects, deterministic, testable
- Warning message examples:
  - Match: `null`
  - Mismatch: `"Build claims STAGING but connected to PRODUCTION Firebase!"`
  - Unknown: `"Connected to unknown Firebase project: xyz-123"`

### Step 2: Create Riverpod Provider

**File:** `lib/config/detected_environment_provider.dart`

**Requirements:**
- Use `@riverpod` annotation (code generation)
- Provider name: `detectedEnvironment`
- Dependencies:
  - `Firebase.app().options.projectId` - actual Firebase project ID
  - `ref.watch(currentOrgProvider).id` - claimed org
  - `ref.watch(currentEnvironmentProvider)` - claimed env
- Call pure function from Step 1
- Return `EnvironmentDetectionResult`

**Implementation Notes:**
- Import `firebase_core`
- Import `environment_detector.dart`
- Import `org_provider.dart`
- This is the ONLY place that reads Firebase runtime config
- Provider auto-updates if dependencies change (unlikely in practice)

**Code Structure:**
```dart
import 'package:firebase_core/firebase_core.dart';
import 'package:riverpod_annotation/riverpod_annotation.dart';
import 'environment_detector.dart';
import 'org_provider.dart';

part 'detected_environment_provider.g.dart';

@riverpod
EnvironmentDetectionResult detectedEnvironment(DetectedEnvironmentRef ref) {
  // Get actual Firebase project ID at runtime
  final actualProjectId = Firebase.app().options.projectId;

  // Get claimed org and env from build-time constants
  final claimedOrg = ref.watch(currentOrgProvider).id;
  final claimedEnv = ref.watch(currentEnvironmentProvider);

  // Call pure function to verify
  return detectEnvironmentFromFirebase(
    actualProjectId: actualProjectId,
    claimedOrg: claimedOrg,
    claimedEnv: claimedEnv,
  );
}
```

### Step 4: Update RescueAppBar UI

**File:** `lib/widgets/rescue_app_bar.dart`

**Current Behavior:**
- Shows single environment chip (red for staging, green for prod)
- Watches `currentEnvironmentProvider`

**New Behavior:**
- Watch `detectedEnvironmentProvider` in addition to current provider
- If match: show single chip (current behavior)
- If mismatch: show TWO chips side-by-side
  - First chip: claimed environment (current styling)
  - Second chip: warning with actual environment (orange)

**Requirements:**
- Import `detected_environment_provider.dart`
- Import `environment_config.dart` (already imported)
- Add `ref.watch(detectedEnvironmentProvider)`
- Update `_buildEnvironmentChip()` method to handle mismatch case
- Return `Row` with two chips when mismatch detected

**Implementation Notes:**
- Keep it simple: only add visual indicator, no dialogs
- Use existing `Chip` widget pattern
- Add small spacing (4-8px) between chips if showing two
- Ensure chips don't overflow on small screens (wrap if needed)

**Code Structure:**
```dart
// In RescueAppBar class
Widget _buildEnvironmentChip(WidgetRef ref) {
  final environment = ref.watch(currentEnvironmentProvider);
  final detection = ref.watch(detectedEnvironmentProvider);

  final chipConfig = getEnvironmentChipConfig(environment);

  // If match, show single chip (current behavior)
  if (!detection.hasMismatch) {
    return Chip(
      label: Text(chipConfig.label),
      backgroundColor: chipConfig.backgroundColor,
      labelStyle: TextStyle(color: chipConfig.textColor, ...),
    );
  }

  // If mismatch, show two chips
  final warningConfig = getEnvironmentWarningChipConfig(detection.actualEnv);

  return Row(
    mainAxisSize: MainAxisSize.min,
    children: [
      Chip(...), // Claimed environment chip
      SizedBox(width: 8),
      Chip(...), // Warning chip with actual environment
    ],
  );
}
```
